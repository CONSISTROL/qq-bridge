## 一、要解决的问题

P1~P3 已经把「收藏表情 / 发图 / 存图 / 按主题搜图」四件事做完了，但 AI 侧仍然只有一个**软策略提示**：

- 它不知道该不该在此刻发表情（不知道距上次发图多久、本轮是否已经发过、对面刚发过图没有）；
- 它不知道收藏里哪一张**对得上当前语境**（备注/笔记是给人看的，模型要自己脑内匹配）；
- 收藏里没有合适的时，它得自己想到「去 B 站搜图」，还得自己拼关键词 —— 实际很少发生。

结果就是：要么不发，要么反复发同一张，要么硬塞一张不相关的。

P4 把这三步做成**一条链路**：判时机 → 本地池打分 → 不够好才联网找。

## 二、设计

```
唤醒提示（每轮）                       AI 主动调用
【此刻发表情包】合适：语境带情绪/梗…     qq_pick_sticker(context/topic/preview/send)
        │                                      │
        └──────────────┬───────────────────────┘
                       ▼
        evaluateMoment()  ← 纯函数：冷却 / 每轮上限 / 严肃语境 / 信号
                       ▼
        rankLocalStickersV2()
          ├─ QQ 收藏表情（state/stickers.json，含备注/笔记/标签/使用次数）
          └─ 本地图库（assets/stickers + index.json，来源白名单 + 尺寸/长宽比过滤）
                       ▼
        pickStickers() 打分排序（中文 bigram 分词 + 标签/意图加权 + 新鲜度 + 尺寸手感）
                       ▼
        低于 minScore？ ──否──► 直接给候选（candidates[i].id 可直接 send）
                       │
                       是
                       ▼
        buildOnlineQuery()：话题词 + 意图词 + 风格偏置（表情包/二次元/Q版/沙雕/梗图/deepseek娘）
                       ▼
        B 站搜图（复用 P3 的 searchImages）→ safeFetchBuffer 并发探测前 4 张
        → 过滤非白名单站点 / 非图片 / 长边 >2000 → online[i].url 可直接 send
```

三条硬边界：

1. **桥接只拦不逼**。时机门说「不合适」时，`send` 直接 409；但门说「合适」也不代表必须发，
   发不发、发哪张仍然是 AI 的决定（`autoUseOnGoodMoment` 默认 false，只留了配置位）。
2. **远程图一律桥接自己下载**（`safeFetchBuffer`：DNS 固定、逐跳重定向校验、禁内网、格式/体积校验），
   绝不把 URL 交给 OneBot 网关去抓 —— 沿用 P1 的铁律。
3. **select 只能从本次候选里选**。`send.id` 必须是本次 `candidates` 里的 id，`send.url` 必须是本次
   `online` 里返回过的 url；其它一律拒绝，避免 AI 自己拼 URL 绕过白名单/体积校验。

## 三、`src/sticker-picker.js`（纯函数层）

无 IO、无副作用，桥接与测试共用：

| 导出 | 作用 |
| --- | --- |
| `tokenize` | 轻量分词：ASCII 词 + 中文 bigram（不引第三方分词库） |
| `detectIntents` | 16 类语境意图（laugh/tease/tired/beg/ai…），返回 id 数组 |
| `looksSerious` | 严肃/敏感语境识别（**带玩笑豁免**，见踩坑 1） |
| `normalizePickItem` | 收藏表情 / 图库条目 → 统一候选结构（`channel` 决定用哪个工具发） |
| `itemText` / `libraryMetaText` | 候选的可匹配文本（图库条目用抓图关键词做锚点） |
| `scoreStickerItem` | 单条打分 0~100：相关度 55 + 新鲜度 12 + 稀有度 8 + 来源 5 + 尺寸手感 ±10 − 最近发过 25 |
| `pickStickers` | 排序 + 截断 |
| `evaluateMoment` | 时机门（allowed / level / reason / cooldownLeftMs / lastStickerMinAgo） |
| `buildOnlineQuery` | 联网搜索词（话题 + 意图 + 风格偏置，提到自己时偏 deepseek娘/小鲸鱼） |
| `buildPickPlan` | 汇总一次选图决策 |

「本轮」的判定：最近一条**别人**的消息之后。不能用「AI 上次发言时间」这类字段当基准
——那些字段容易被别的路径写歪，导致每轮都被判成 0 张（踩坑 3）。

## 四、桥接侧（`src/bridge.js`）

- `readPickConfig()`：读取 `socialV2.sticker.pick` 并补默认值。
- `loadImageLibrary()` / `stickerLibraryItems()`：图库**目录扫描兜底 + index.json 元数据合并**
  （index 里没有的图也能被选到）；再按来源白名单 + 最长边 + 长宽比 + 体积 + 排除 `p1-test` 过滤。
- `rankLocalStickersV2()` / `buildStickerMomentLineV2()`：只读的本地排序与提示生成；
  后者被注入 `buildWakePromptV2()` 与 `/api/socialV2/prompt`（`stickers.moment`）。
- `buildStickerPickResultV2()`：本地 + 联网兜底，返回候选、联网结果、时机、提示。
- `buildStickerPickPreviews()`：最多取 2 张候选图（收藏表情走收藏 URL，图库直接读文件）以 base64 交给 MCP 层。
- `sendPickedStickerV2()`：真正发送（收藏表情走 `sendStickerV2`，图库/联网走 `sendImageV2`），
  并复用 `sendChain` 保证「先文字后表情」的顺序、写 `recentStickerIds` / `lastStickerAt`。
- 路由 `POST /api/socialV2/pick-sticker`：候选查询与发送同一个入口（`send` 字段决定是否真发）。
  发送前过 `sendTimes` 限频（与 `qq_send_sticker`/`qq_send_message` 同一档额度），
  联网查询才吃 `image.maxPerMinute` 额度（纯本地查询不吃）。
- `/api/socialV2/states` 每个会话多返回一段 `sticker`（此刻是否适合、冷却余量、本轮已发几张、候选池大小），
  控制台可直接看到。

## 五、MCP 工具（`src/mcp-snowluma-safe.js`）

`qq_pick_sticker`（开关 `socialV2.tools.pickSticker`）：

| 参数 | 说明 |
| --- | --- |
| `context` | 当前语境/心情（不传则用会话最近消息自动判断） |
| `topic` | 话题词（联网找图时用） |
| `limit` / `minScore` | 覆盖配置的候选数与合格分 |
| `searchOnline` | 强制/禁止联网兜底；不传=本地不够好时自动联网 |
| `preview` | 把候选图直接返回给视觉模型看（最多 2 张） |
| `send` | `{id}` 发本地候选、`{url}` 发联网候选，可选 `replyToMessageId` / `atUserId` |

## 六、本地池补库（`scripts/fetch-style-stickers.mjs`）

按风格关键词抓图进 `assets/stickers/`，写 `index.json`（`{version,updatedAt,items,outDir}`）：

```bash
node scripts/fetch-style-stickers.mjs                       # 默认关键词，上限 60
node scripts/fetch-style-stickers.mjs --keywords "小鲸鱼表情包,deepseek娘" --per-keyword 8
node scripts/fetch-style-stickers.mjs --max-bytes 4194304   # B 站图偏大，2MB 会砍掉约 1/4 候选
node scripts/fetch-style-stickers.mjs --animated-only       # 只留真动图（按帧数探测）
node scripts/fetch-style-stickers.mjs --dry-run
```

实测一次（`--limit 40`，带 cookie）：候选 36 → 下载成功 27 → **入库 26**（items 20 → 46），
幂等复跑新增 0。出图质量：`deepseek 表情包` / `deepseek娘` / `小鲸鱼表情包` 最好；
`猫猫表情包` 容易出手机相册式图墙截图；`二次元表情包` 多为大尺寸插画。
换新关键词才有新图（同一批关键词第二次跑基本 0 新增）。

## 七、配置（`socialV2.sticker.pick`）

```jsonc
"pick": {
  "enabled": true,              // 时机判断/推荐总开关
  "hintInPrompt": true,         // 唤醒提示里带「此刻适不适合发表情」
  "autoUseOnGoodMoment": false, // 预留：时机好时自动帮 AI 挑好（当前不自动发）
  "minIntervalMs": 90000,       // 两次表情之间的硬冷却
  "maxPerTurn": 1,              // 单回合最多几张
  "minScore": 30,               // 本地合格分；低于它才联网
  "defaultLimit": 5,            // 默认返回候选数
  "includeLibrary": true,       // 本地图库是否参与候选
  "onlineFallback": true,       // 本地不够好时联网找
  "onlineCount": 6,
  "styleKeywords": ["表情包", "二次元", "Q版", "沙雕", "梗图"],
  "librarySources": ["style", "manual", "ai"],
  "libraryMaxSide": 2600,
  "libraryMaxRatio": 2.0,
  "libraryMaxBytes": 3145728
}
```

控制台入口：**07 二代仿真模式 → 表情包时机与选图**（另有 `qq_pick_sticker` 工具开关）。

## 九、踩坑记录

1. **「哈哈哈哈笑死了」被判成严肃语境。** 严肃词表里有「死了」，而最该发表情的语境恰好是「笑死」。
   加了玩笑前缀豁免（笑死/笑不活/笑疯/笑喷/乐死…）。**没有单测就会一直拦掉最该发的情形。**
2. **收藏表情的发送通道在测试里过不去。** `sendStickerV2` 会对表情 URL 调 `safeFetchBuffer`，
   而它正确地拒绝 127.0.0.1 —— 这是 SSRF 防护的预期行为。E2E 因此改走「本地图库 → `qq_send_image`」
   通道（直接读盘，不涉及 URL 白名单），收藏表情通道由既有 `test-stickers.mjs` 与线上使用覆盖。
3. **「本轮已发几张」不能靠 `lastUserTurnAt` 这类字段。** 该字段没有被稳定写入，导致每轮都算成 0 张。
   改成用时间戳与「最近一条别人的消息」比较。
4. **图库条目没有含义描述。** 抓图脚本只能给出关键词与评论摘要，模型光看 label 选不准；
   于是 `itemText` 用抓图关键词（剥掉「表情包/表情/动图」这类通用词）当匹配锚点，
   再给 `qq_pick_sticker` 加了 `preview` 让模型真的看图。
5. **资讯配图混进候选。** 图库里的 `bili-cover`/`bili-dynamic` 是影视飓风动态配图，
   与表情无关却因为「没文本=中性底分」排到了前面。改成来源白名单 + 长宽比过滤 + 尺寸手感分。
6. **`config.json` 又被行级手术差点搞坏。** 这次全程用「JSON 解析 → 改对象 → 写回」并先备份
   （`config.json.bak-pick-p4`），写完校验顶层键数、白名单与 ownerQQ 未变。
7. **控制台 token 有长度/字符校验**（≥16 位、`[A-Za-z0-9_-]`），E2E 里用 `e2e-token` 会被忽略并
   回退到随机 token，表现为 401。测试里改用合规的固定 token。
8. **`pkill -f "src/bridge.js"` 会把当前会话的 dsh 也带走**（dsh 的 cwd 就在仓库里，
   命令行里带得到处都是）。重启线上实例要按 PID 精确 kill。
